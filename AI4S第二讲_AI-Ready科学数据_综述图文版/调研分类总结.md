# AI-Ready 科学数据：分类调研与教学转化

检索截止：2026 年 9 月 28 日（美国太平洋时间）。公开接口的 UTC 采集时间保存在资源快照中。本报告采用定向范围调研，优先查阅机构报告、原论文、作者代码库、官方数据卡与教程；不声称穷尽全部研究，也不把搜索排序当作学术影响排名。

## 1. 这次调研改变了课程的哪些判断

**AI-Ready 的核心是“针对某个任务，数据是否已经具备可用条件”。** 同一份胸片与报告可以支持图文表征训练，但若报告已经放入模型输入，就不能再用它证明模型能独立读图。课程采用“任务与信息边界、科学含义、可执行加工、独立质量证据、可复用交付”五方面的教学定义。这是对多份来源的综合，不宣称存在一项统一国际认证。[ISC / CODATA 报告](https://council.science/publications/data-and-ai-for-science/)、[ORNL 技术框架](https://arxiv.org/abs/2507.23018v1)、[SciDataCopilot](https://arxiv.org/abs/2602.09132v1)从治理、计算准备和科学任务三个角度提供依据。

**“能变成 token”只回答输入接口问题。** 文本、DNA 序列、像素块、复数信道、原子图和时空场可以使用不同编码方式。科学数据还要说明单位、坐标、参考系、生成条件、样本关系和标签来源。The Well 保留时间、空间及物理场结构，OpenGenome2 区分 FASTA 与预训练 JSONL，WeatherBench 将变量、层、网格和时效统一到可评测的数组。它们展示了接口适配之前仍需完成的科学工作。[The Well](https://polymathic-ai.org/the_well/api/)、[OpenGenome2](https://huggingface.co/datasets/arcinstitute/opengenome2)、[WeatherBench 数据指南](https://weatherbench2.readthedocs.io/en/latest/data-guide.html)。

**“五层科学知识”与“就绪程度”属于不同坐标。** 指定综述提出事实、理论、方法与技术、建模与仿真、洞见五层，用来解释知识内容。ORNL 的 Raw / Cleaned / Labeled / Feature-engineered / AI-ready 则刻画技术准备过程。一个原始实验记录属于事实层，也可以成为整理完备的 AI-ready 样本；一个高层洞见仍可能证据不足。教学必须先讲清五层“各自装了什么”，再讨论“针对什么任务准备到了什么程度”。[指定综述 §2.2](https://arxiv.org/abs/2508.21148v2)、[ORNL §4](https://arxiv.org/abs/2507.23018v1)。

**训练材料要按学习信号细分。** 预训练可以从序列延续、掩蔽恢复或图文关系学习；SFT 学习认可的任务回答；解释型后训练提供文字化推理监督；工具轨迹记录真实动作与返回；偏好对比较候选；在线 RL 还需要可重复运行的环境和奖励；独立评测保留不参与这轮训练的参考。MedReason 的解释文本与 MedAgentBench 的 FHIR 操作不可合称为同一种轨迹。[MedReason](https://arxiv.org/abs/2504.00993)、[MedAgentBench](https://doi.org/10.1056/AIdbp2500144)。

**闭环治理可以更新数据，也可以更新加工方法。** SciDataCopilot 展示面向任务的执行与修复；Humanlaya 将当前任务包修复与下一批质检方法更新分开。只有保存、调用和检验了后继版本，才有跨轮次的改进证据。一次调用大模型清洗文件或反复重试成功，不足以证明完整 RSI。[SciDataCopilot](https://arxiv.org/abs/2602.09132v1)、[The Last AI Built by Humans §5.4](https://arxiv.org/abs/2609.11873v3)。

## 2. 演进脉络：为什么会提出 AI-Ready

- **2016：复用条件成为共同语言。** FAIR 将标识、访问、互操作和复用从“附带文档”提升为科研数据本身的要求。
- **2019–2022：任务数据与透明文档成熟。** MIMIC-CXR、PubMedQA、Datasheets 与 Data Cards 让人们更明确地区分记录、标签、任务与使用限制。
- **2023–2024：数据配方开始接受受控比较。** DataComp / DCLM 固定模型和预算比较数据；Croissant 让文件与字段可被工具理解；Mol-Instructions、PubMedVision 把科学记录转成不同监督形式；The Well 统一物理场接口。
- **2025：科学基础模型使“数据包”更加复杂。** OpenGenome2、OMat24 / OMol25、Intern-S1 等强调大规模科学表示；HealthBench、MedAgentBench 则把“考试”扩展到开放回答和可执行环境。RDA／Microsoft 与 ISC／CODATA 同时强调制度、元数据和研究人员技能。
- **2026：研究重心继续进入任务语义、自动加工和可复现执行。** SciDataCopilot 组织科学任务工作流；Croissant Baker 自动构造元数据；Croissant Tasks 描述评测任务与解法；FOXDEN 连接实验设施谱系与发布；Domain Bounds 检查“数值看起来正常，复用语境却错了”的问题。

这条脉络是教学综合，并非一种技术替代上一种。FAIR、学科解析器、数据配方和智能体工作流今天仍共同存在。各阶段对应原始资料见后面的分类条目。

## 3. 六种分类角度，应分别回答六种学生问题

1. **按学科与科学对象：研究的是什么。** 患者、蛋白、分子、晶体、信道、天气场、芯片设计、程序版本和地块，其独立单位不同。
2. **按模态与表示：一条记录长什么样。** 图像 / 体数据、序列、图、公式、表格、时序和场。格式是载体，如 DICOM、FASTA、CIF、HDF5、NetCDF、Zarr、JSONL；同一模态可以使用不同格式。
3. **按知识层次：这份材料告诉我什么。** 观测、理论、方法、模拟、洞见分别有不同的证据责任。
4. **按证据来源：为什么相信这个值。** 实验测量、数值模拟、专家注释、程序派生和模型合成分别记录，不能混作实测真值。
5. **按模型用途：它怎样产生学习或评价信号。** 预训练、SFT、解释 / 工具轨迹、偏好 / RL、RAG / 工具上下文、独立评测。推理使用通常不直接更新模型权重。
6. **按技术准备：还差什么才能用。** 可读、语义明确、关联正确、质量可检验、任务接口匹配、能复现和交付；成熟度必须针对任务解释。

例如 `I01.dcm` 的回答可以是：医疗 / 一次检查、二维影像 / DICOM、事实记录、设备观测、图文预训练输入、仍需核对视位并按患者划分。学生能完成这样的描述，比背诵一串原则更接近真实技能。

## 4. 技术框架：从原始资料到可检查的数据产品

**入口是任务说明。** 明确希望模型预测、生成、调用工具还是接受考试，同时列出使用时真正可获得的信息。示例：影像报告生成允许看哪些视图，是否允许看历史报告，答案依据由谁提供。

**第一组加工负责“认对对象”。** 固定数据快照和许可，解析原始格式，建立实体与样本主键，连接多模态。胸片用患者—检查—图像层级，分子先处理同一结构的不同字符串，遥感依据坐标与时间配准。

**第二组加工负责“保住科学含义”。** 校验单位、坐标、采样率、参考系和测量方法；记录缺失、失败、不确定与异常。温度换算只是一个例子，天气重网格、信道复数表示、蛋白残基映射和表格列关系都是实际工作。

**第三组加工负责“造对监督”。** 把原始记录转换为配对关系、问题与目标、动作与结果、候选偏好或冻结参考。每一种都需要来源证据，不能把语言润色当作科学核验。

**第四组加工负责“支持可信训练与复现”。** 先按科学对象和未来泛化目标划分；只用训练部分拟合统计量；生成张量 / 图 / token 及适当分片；交付数据卡、机器可读清单、检查记录、转换程序、版本与校验值。

**工具按工作选择。** Docling / MinerU 处理文档入口；RDKit / xarray / MNE / TorchGeo 保留学科结构；DataTrove / Data-Juicer / NeMo Curator / DataFlow 组织加工；Croissant / DVC 记录接口与版本。工具的自动化覆盖范围与科学验证责任必须同时讲清。[工具分类详见目录](resources.html)。

## 5. 医学贯穿案例：三种原料必须看出区别

**A. 预训练配对。** 原料可以是同次胸片检查的图与报告，也可以是论文图与图注。加工后保留图片引用、文本、配对组、来源版本和训练划分。训练信号是“哪些信息属于一起”或自监督恢复目标。BiomedCLIP 的 PMC-15M 展示规模化配对；MIMIC 展示临床记录层级。它们不是同一个数据集，不混用数量和许可。

**B. 后训练材料。** 先用 PubMedVision 说明同一来源如何构造对齐 VQA 与指令 VQA，再用 MedReason / ReasonMed 解释文字化推理监督，用 MedRAX / MedAgentBench 解释工具动作、参数、结果、证据与终止状态。经核验的好轨迹可用于 SFT；同一输入下的候选比较可形成偏好对；在线 RL 则需要策略采样、环境反馈、奖励版本及独立检验。课程中的轨迹 JSON 是明确标注的教学结构，不能冒充这些论文直接公开的训练文件。

**C. 独立评测材料。** 模型只取得任务与允许输入；评测程序取得独立专家参考、rubric 或环境状态检查；开发调整使用验证集，最终结果在冻结测试上报告。HealthBench 的每题 rubric 和 MedAgentBench 的环境结果检查说明“正确”可以采用不同可执行定义。患者、题源、工具环境和索引都可能造成泄漏。

学生最终应能指认五件事：哪个文件是输入，哪个字段是学习目标，谁核验过它，训练时是否更新权重，独立评测参考怎样隔离。第 39 页和可下载模板直接检查这五件事。

## 6. 把方法迁移到自己的研究方向

- **通信：** 由场景参数生成复数信道，构造信道补全或场景对齐样本；记录选波束—仿真—反馈的决策过程；用新街区 / 新轨迹及固定码本检验。
- **芯片：** 对齐网表与布局，构造掩蔽连接或拥塞监督；记录修改动作及 EDA 返回，连同时序失败一起保存；用新设计族和固定工具条件检验。
- **生物：** 区分 DNA 预训练、蛋白功能监督、酶—反应记录和湿实验验证。SciDataCopilot 的 214,104 条酶反应记录把序列、催化描述和底物—产物 SMILES 连起来；不能将其规模优势表述为对每一个酶家族都更好。
- **材料：** 用结构、计算设置、能量与力形成计算样本；记录候选生成、收敛检查与筛选；按组成族、结构原型或时间确定泛化目标。实验与 DFT 标签分别描述。

## 7. 当前实现程度与仍未解决的问题

**已经能复用的部分：** 多种公开数据产品、学科解析器、规模化清洗和元数据工具已有代码与教程。是否适用于学生项目仍取决于版本、硬件、许可和具体任务。

**正在发展的部分：** 任务驱动的科学数据智能体、自动生成元数据、机器可读评测、使用语境约束，以及在后续批次中继承的治理方法。2026 年预印本提供了明确方向，但不应将作者的有限用例结果升级为普适能力。

**值得继续研究的具体问题：** 怎样验证模型生成的标注而不循环自证；怎样覆盖失败实验与稀有条件；怎样同时防止患者、同源序列、空间邻近与检索库泄漏；怎样跨机构保留科学语义和用途许可；怎样记录数据对某次训练的实际贡献；怎样判断自动改进规则在新批次仍有效。

## 8. 学生视角的教学设计原则

每页以一个学生问题开始，给出可观察的样本、原论文证据或可执行结果，再解释术语与方法。抽象结论后必须有可核对的反例或边界。资源推荐要告诉学生第一步打开哪个文件、检查什么字段、产出什么，而不止展示项目名。

新版 60 页以指定综述顺序组织，领域实物与医学连续案例辅助理解；原图、讲义、交互和资源目录供按需展开。正文承担课堂理解，扩展内容承担教材复习。全校通识课程聚焦 AI-Ready 科学数据，不加入大数据平台架构或分布式文件系统课程。

课后可形成的最小技能产物包括：一张样本说明卡、一个可追溯的加工小流程、三类数据包的结构草案，以及一份独立验证方案。它们作为自选练习和模板资源提供，不设置离堂任务。

## 9. 热度快照与使用限制的解释

GitHub stars 是关注量，Hugging Face `downloads` 按平台近月统计口径记录，均不是独立用户数、论文引用量或科学质量评分。大型数据集使用外部存储、自定义脚本或多个子仓库，下载量可能无法直接横向比较。只比较本轮明确选取的条目，不称为全球排名。[Hugging Face 官方统计说明](https://huggingface.co/docs/hub/datasets-download-stats)。

#### FAIR Guiding Principles

- 年份 / 状态：2016；期刊论文；国际科研数据社区。
- 学科 / 用途：跨学科；治理、共享。
- 提供什么：可发现、可访问、可互操作、可复用的原则框架。
- 怎样实现：把数据标识、机器可读元数据、访问协议和复用许可作为可交付内容。
- 证据与边界：FAIR 没有承诺标签正确或模型泛化，也不要求所有数据无条件公开。

#### Croissant：ML-Ready 数据元数据

- 怎样实现：识别格式结构后建立字段和资源描述，并检查结构保真。
- 证据与边界：自动推断结构不能替研究者决定临床或科学语义，仍需复核。
- 学生第一步：比较 CSV 与 DICOM 的字段描述，指出哪些含义需要领域专家。
- 来源：[主要来源](https://arxiv.org/abs/2605.15079v1)。

- 学生第一步：把“测什么”和“某模型怎样完成测试”分开写成两个清单。

### RSI 与反馈治理（3 项）

区分修复当前材料与改进后续方法。考察改进是否被保存、继承并在新任务上检验，同时监控数据分布与独立性。

#### The Last AI Built by Humans

- 年份 / 状态：2026；用户上传预印本 v3；Duan 等。
- 学科 / 用途：跨学科；RSI、持续治理。
- 提供什么：区分本次输出修复、持续改进及改进机制的跨轮次继承。
- 怎样实现：Humanlaya 的内层修任务包，外层改质检方法，经留出检查与人工把关后用于新批次。
- 证据与边界：自主性级别不等于质量等级；企业内部对比与独立复现须区分。
- 学生第一步：先修复一次扫描件，再更新会被下一批继承的检查规则。
- 来源：[主要来源](https://arxiv.org/abs/2609.11873v3)。

#### STELLA

- 年份 / 状态：2025；预印本 v1；Jin 等。
- 学科 / 用途：生物、科研工作流；工具经验、反馈。

- 证据与边界：本课沿用指定综述引用的 v1，不把更晚版本结果混入同一证据。
- 学生第一步：检查一次任务留下了数据、工具代码还是任务模板，以及下次如何调用。
- 来源：[主要来源](https://arxiv.org/abs/2507.02004v1)。

#### 递归合成数据与模型坍塌

- 年份 / 状态：2024；Nature 论文；Shumailov 等。
- 学科 / 用途：跨学科；合成数据、反馈风险。

- 证据与边界：结论依训练和数据替换设置，不应简化成“所有合成数据都不能用”。
- 学生第一步：为真实、模拟、合成记录保存不同来源，并跟踪罕见条件覆盖。
